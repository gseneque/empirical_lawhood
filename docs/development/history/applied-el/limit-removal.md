This is a historical record of the 11 October 2026 allocation and its producing implementation.
It does not override finite budgets in a later selected profile, frozen plan or current reader.
For new work, select the [documented workflow](../../../reference/workflows.md), [environment](../../../using/environments.md) and explicit storage paths.

The user approved reopening and then instructed **“Yeah remove the limits”** on
11 October 2026. This revision removes the operational restrictions identified
in the [limits audit](limits-audit.md) from the active applied EL programme.
It supersedes the original RA0, Rubisco proposal and battery D1 resource caps.

The user's later instruction retains every limit necessary for scientific
integrity and prioritizes actual Rubisco/TOP5 execution and results. Exact
scientific identities, cutoffs, assay compatibility, complete denominators,
independent units, negative outcomes and genuine authority remain binding.

These are genuine optional limits, rather than larger replacement constants.
Finite budgets remain available for callers that explicitly select them. A finite
authority ceiling cannot admit an unrestricted request. Existing finite canonical
records retain their original bytes and meanings.

The shared inquiry policy applies cost-based refusal only to selected finite
ceilings. Unknown prior costs cannot cause a resource stop when no resource ceiling
exists. Source/cutoff eligibility, unknown scientific operands, exact endpoint
joins and scientific negative outcomes retain their evidential meanings.

The current CPU/core and GPU counts describe execution placement and the selected
CPU implementation. They do not create duration budgets. Individual native effects
retain their one-contact custody rule: a retained or ambiguous contact cannot be
replayed as a repair. Further authorized investigations receive distinct task and
source identities and retain all earlier outcomes. Ordinary engineering repair has
no programme-wide attempt ceiling.

## Producing code and execution selections

The active Rubisco, analytic-material and battery thermal bindings select
unrestricted memory, wall time, output and scan budgets. The executor skips
`RLIMIT_AS`, `RLIMIT_CPU`, output resource limits and fixed-duration termination
for those selections. Recursive authoring, decisions and portable contributions
use complete exact member inventories without the former study payload or
ancestry ceilings. Stable file reads still reject links, replacement, growth,
truncation and digest substitution.

Source provenance no longer has its former 16 MiB per-file, 8,192-file or
256 MiB aggregate limits. Scientific configuration nesting/node counts, graph
counts and multiplicities have no study ceiling. Actual inventories remain
complete, sorted, unique and authenticated.

`ArtifactCustodyLimits` gives record, manifest, recovery, raw-source, internal
batch and canonical JSON resource allowances unrestricted defaults. This removes
the former 32 MiB convenience/recovery, 16 MiB receipt, 1 MiB manifest/token,
128-level JSON and 256-member/1 TiB internal batch stops, together with fixed
recovery task/attempt/candidate and semantic-registration counts. Finite callers
can explicitly select positive ceilings. Exact member sets, immutable publication
and receipt joins, strict formats and unsafe-serialization refusal still apply.
Current readers retain producing validator identities as provenance and validate
the original bytes with installed format contracts. Historical validator sources
and predecessor-hash admission lists are retired.
