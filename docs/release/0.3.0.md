# Empirical Lawhood 0.3.0

SPDX-License-Identifier: CC-BY-4.0

This note describes the changes from software version 0.2.0.
It separates release verification from scientific results and qualification.
Use the migration links before adapting an existing workflow.

## Changes

- Recursive inquiry workflows represent requirements, selected operations and
  their dependencies. Source, configuration, execution and authority keep
  separate contracts.
- Matrix programme execution uses native direct-input contracts, authenticated
  dependency operands and receipt-based recovery. Reports retain whole-root
  denominators, interrupted attempts and unevaluable outcomes.
- Source and custody reads reuse authenticated members within an operation.
  Fresh snapshot checks, original evidence identities and consumer refusals
  remain in effect.
- Nine research programmes organise study designs, findings, run guides and
  editable inputs across Foundations, Materials, Energy and Biology.
- Bounded CI checks selected contracts, generated files, documentation, exact
  distribution contents and installed workflows. Larger test profiles remain
  separate selections.

The [changelog](../../CHANGELOG.md) gives more implementation detail.
The [programme index](../../programmes/README.md) links findings and their limits.
The selected published preprint remains edition 0.60 with its original assets.

## Installation and migration

Download the wheel or source distribution from the
[v0.3.0 release](https://github.com/gseneque/empirical_lawhood/releases/tag/v0.3.0).
Verify the download against the release's `SHA256SUMS` file.
Follow [getting started](../getting-started.md) and select the documented environment.
Native workflows require their separate locked environments and actual inputs.

Workflow IDs and command names remain unchanged by the documentation move.
Scientific records and run guides now live under `programmes/`.
Shared procedures live under `docs/using/`, with references under `docs/reference/`.
The [workflow catalogue](../reference/workflows.md) gives current locations.

Consult the [compatibility guide](../development/compatibility.md) for API changes.
In particular, the three named SDK authoring functions require a guarded
`artifact_writer`.
Use current editable examples for new development work.
Keep retained scientific configurations and records unchanged in their original custody.

## Verification and evidence limits

The retained local bounded CI run passed 1,035 tests on development commit
`4b38b01cc736a7fab3771d33e2ce8e40dafffb46`.
Its 22 command stages included lint, ten generator checks, documentation,
distribution comparisons and installed-wheel checks.
All 174 installed command-help checks and the exposed workflow examples passed.
The publication commit has separate metadata, history and artifact bindings.
The release's verification record identifies those bindings and the actual hosted checks.

An earlier complete portable run failed: 14,968 tests passed, 607 failed and
506 had setup errors.
Focused repairs subsequently passed 1,112 affected cases and removed one
obsolete redundant case.
The original failed packet remains unchanged.
No complete portable-suite pass is claimed for the publication commit.
The bounded CI result does not establish native, held-input or complete portable coverage.

This release binds retained scientific findings without new scientific acquisition.
Development results and software controls do not establish fresh qualification.
Programme reports retain negative results, incomplete acquisition and conditional nonentry.
Historical primary evidence remains in external custody, with availability limits in
the [reproducibility statement](../../REPRODUCIBILITY.md).
