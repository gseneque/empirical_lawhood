# Implementation coverage and evidence limits

SPDX-License-Identifier: CC-BY-4.0

This map identifies current implementation owners and the limits of their evidence.
The [workflow catalogue](../reference/workflows.md) owns advertised operations,
inputs and first stops. The [release inventory](release-inventory.md) owns shipped
surfaces; the [external release selection](release-status.md) binds accepted
source, artifacts, scientific results and review. Historical development
checkpoints do not establish acceptance of a later candidate.

The software release and its retained scientific results have separate acceptance boundaries.
The selected release record states which results, profiles and reviews it includes.
A Matrix programme retains every assigned phase and authentic conditional nonentry.
An unavailable required model cannot be replaced by a refit, fallback or new cohort to complete a release.
Component checks, historical observations and exposed demonstrations retain their original scopes.
They supply no fresh assignments or missing authority.
This implementation map commissions no new scientific programme.
