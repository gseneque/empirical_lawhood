# Version 1.0.0: contributor interfaces and ownership

SPDX-License-Identifier: CC-BY-4.0

This release consolidates EL around its recursive scientific workflow.
It gives investigation, method and domain contributors supported entry points and shared operational services.
Use the [three-job index](../v1.0/README.md) before selecting a contribution.

## Public routes

The [investigation guide](../v1.0/define-investigation.md) derives a plan from its scientific definition, executes it and inspects original results.
The [method guide](../v1.0/add-method.md) adds a callable calculation with explicit applicability and strict input/output contracts.
The [domain guide](../v1.0/add-domain.md) supplies meaning and transformations, with optional native contracts when required.

A new local workspace derives its profile from one explicit user-selected root.
Shared resource selection observes usable capacity and retains the declared method requirements and numerical settings.
A routine extension exports one `ExtensionDeclaration`.
The existing generators derive its registry, discovery and executable products.

The [new R01–R22 experiments](../v1.0/joint-description-experiments.md) compose
response-law construction, safe action selection and finite-menu economic
assessment under the broader joint-description hypothesis. All families have
editable recipes and a shared six-stage causal protocol. Twenty preprint-inspired
studies completed the primary CPU protocol. R14 and R16 await physical inputs.
R17 and R22 contributed CPU results and retain separate GPU qualifications as
follow-ups. [Scientific findings and producing sources](../../programmes/shared-records/joint-description-results.md)

## RC2 foundations synthesis studies

Five numerical studies examine entropy production, predictive memory and response to intervention. Three use stochastic matrices, one uses a thermal circuit and one uses a monitored event chain. Each result has a scientific definition, a run guide and a portable record of the original evaluation. The shared path-ensemble workflow prepares the selected design, runs it through the recursive investigation service and reads the results. [Studies 1–5, findings and run guides](../../programmes/foundations/README.md#foundations-synthesis-studies)

## Ownership and breaking source changes

Scientific contracts now live in named `science` subpackages.
`design`, `methods`, `domains`, `adapters`, `execution`, `storage`, `api`, `cli`, `workbench` and `package_data` have explicit responsibilities.
The [complete migration map](../development/v1-module-migration.json) locates every moved file and module.
The [architecture gate](../../tests/test_import_boundaries.py) enforces dependency direction and removed paths.

Retired Python module paths are absent.
There are no old-path aliases, compatibility packages or legacy wrappers.
Consumers must update imports to the documented v1.0 interface or current owning module.
Undocumented implementation helpers remain internal.

## Inspection and diagnosis

Preparation reports trace authored scientific choices to generated operations and implementation owners.
Shared application diagnostics identify the operation, failed contract, responsible layer, public expected/actual state and retained evidence location.
CLI and workbench present the same application results.

Inspection authenticates retained original products.
Recovery preserves completed work, attempt ancestry and uncertain native effects.
Moving software between packages supplies no permission to replay scientific work.

## Preservation and evidence limits

Original scientific records retain their exact bytes, schema identities, outcome censuses and accepted scientific meaning.
Executable source and its implementation identity change honestly with the migration.
The selected preprint remains edition 0.60.
Current scientific work orders retain their original scope and custody.

The [release evidence packet](release-status.md) records the exact executed checks, source and artifact identities, and any unperformed acceptance.
This release note is a description of changes, not a second mutable acceptance record.
No new scientific qualification, cloud acquisition, public publication or hosted release is implied by the version number.
Use the existing [release selection contract](release-status.md) for publication and separately selected scientific acts.
