# Design and run an experiment

SPDX-License-Identifier: CC-BY-4.0

This guide gives instructions for scientific design, candidate construction and the separately authorized experiment lifecycle.
It applies to the checked family boundaries in the route register.
Use it to select a route and identify its first missing input.

Select a [retained route](../reference/capabilities.md).
Its quick start must identify the actual native or post hoc input, install group, scientific check and supported boundary. A static adapter or capability registration is not an
executable experiment. The [CLI reference](../reference/cli.md) lists every installed
command and its typed inputs.

## Researcher procedure

1. Choose a supported guide from the [workflow index](../reference/workflows.md).
   State the question, scientific scope, independent units, cutoffs and complete
   assigned census before selecting a design. For Matrix E1–E6, start with the
   [programme guide](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md) and its scientific
   specification.
2. Select the guide's [environment](environments.md), source installation,
   operator profile and explicit input, output, scratch and cache destinations.
   Check the actual source access and capacity required by the selected graph.
3. Copy the documented editable inputs, preserve their originals, and use
   [configuration preparation](configuration.md). Follow the guide's explain,
   prepare and author steps, retaining their returned identities and paths.
   Resolve each reported prerequisite through its owning procedure.
4. Obtain genuine issue, execution and reveal authority where the guide requires
   it. Run the frozen design through its public command. A development example
   or static preparation does not supply these acts or fresh evidence.
5. Inspect the owning scientific readout and retained attempt records. Keep
   negative, missing and unevaluable outcomes in their assigned denominators.
   Follow [receipt-based recovery](results-and-failures.md) for interrupted work;
   do not reacquire an uncertain native effect or replace an adverse result.
6. Export through the guide's supported route and retain the exact source,
   configuration, calibration, receipt and publication references needed to
   reproduce the reductions. State the finding, uncertainty, assumptions and
   limits separately from operational success.

The selected guide owns the exact commands and family-specific boundaries.
Researcher use does not require the maintainers' local work plans or storage mount.

## Follow one scientific composition

A workflow selection chooses an existing input and operation boundary.
A scientific composition binds a producer's exact evidence to a later consumer.
An application composition binds the providers, codecs, storage and authority ports for that design.
A workflow label or registered provider does not create a scientific parent.

Consider the [current finite-response family](../../programmes/foundations/emergent-structure/workflows/finite-response-law/guide.md).
The question is whether a fixed nominated predictor supports forecast-mediated use on a separate prospective cohort.
The native source supplies prepared states and responses.
The calibration and qualification methods assess the fixed predictor.
The evaluation controller freezes forecasts before request and future-outcome reveal.
The nomination retains its original development evidence.

Use the family guide's returned paths and identities.

Native and qualification parents can come from separate issued runs.
Both publications and grants must authenticate.
`finite-response-bind-runtime` binds actual current authorities after issue.

Read scientific fields through `finite-response-result`.
Read execution state through `campaign status`.

Runtime binding creates no authority.

The scientific lineage identifies each later stage's evidence dependencies.
The scientific-operation graph identifies required source, method and control operations.

Requests, arms and numerical views remain nested within the 32 calibration or 64 evaluation roots.

An allocation proposal, permitted copied configuration and output location are editable inputs.
Fixed coefficients and scientific specifications retain their owning contracts.

Relabeling or repeated acquisition cannot produce a qualified evaluation parent.

## Turn a missing requirement into an experiment

Use the [recursive inquiry workflow](recursive-inquiry.md)
when a question needs a proposed supplier investigation, explicit joins or a
later use of an assessed contribution. A partial programme can retain unavailable
suppliers and unresolved decisions. Select a finite closed wave before compiling
or acquiring evidence. The authoring projection and task plan must preserve the
same requirements, cutoffs, scopes, parent roles and complete assigned census.

State separately whether the supplying procedure is supported, whether it
actually supplies the condition on this instance, whether the consumer admits
that product at its cutoff, and whether the joined use succeeds. A later
investigation acquires or assesses its own further scientific product. Importing
a prior manifest does not execute that application or create new confirmation.
The materials example retains distinct material A, device and material B subjects;
fabrication, instrument response, resolution and qualification remain unresolved.

The [RC prerequisite experiment](../../programmes/foundations/measurement-and-response/workflows/rc-prerequisite-chain/guide.md) starts with a task for a fixed response package.
That package requires the capacitor voltage to lie inside its support.
Preparation is a candidate supplier of that condition.
Its decision rule requires an adequate voltage observation before the decision cutoff.
Each connection has its own claim and falsifier:

| Claim | Supplier and consumer | What can refute the connection |
|---|---|---|
| RC-M | Voltage observation → frozen preparation rule | Wrong quantity, units, source or receiver; late or missing information; excessive uncertainty; a reported interval that fails to contain the sampled state |
| RC-P | Selected discharge → unchanged response-package support | An inadmissible handoff, inadequate prospective guarantee or actual state outside support at the committed response cutoff |
| RC-J | Complete observation/preparation/response procedure → terminal task | An inadmissible handoff, failed support, numerical defect, missed completion deadline or failed terminal task |

The finite preparation menu and decision rule freeze before observation.
Only admitted observation values guide the choice.
Simulator truth permits assessment of the observation and prepared state after commitment.
It cannot replace a missing observation or revise the chosen duration.

Unchanged, wrong and insufficient preparation arms use the same downstream package and limits.
A preparation that supplies support can still fail the joined task's completion deadline.
A coincidentally accurate endpoint outside support remains declined package use.

This is prerequisite recursion: a consumer's missing condition becomes a further scientific question.
The supplied example closes two numerical connections and stops at unsupported physical sensing and component metrology.
Its eleven deterministic preparations are the complete development denominator.
Their controls, solver views and clocks remain nested within those units.

Operational sequence, evidence that a condition is supplied, and statistical nesting make distinct claims.
The existing finite-response composition described above has its own design and evidence.
This RC example supplies no qualification for a joined use of the paper's separate studies.

## Freeze the scientific design

Before outcome contact, declare the source and license/access basis, native
parameters and units, coordinate frame, denominator and preparation history. Write the requested action.
Write the native-delivery observation, receiver and horizon.
Write the cutoff, independent-unit rule, nested numerical views, controls and decisive falsifier. Separate development units from new evaluation units. The quick-start configs are development examples.

Exposed unit IDs, seeds or
outcomes cannot become a new unexposed evaluation cohort by changing an
experiment ID. Methods attach to the named consuming native route. A post-hoc method needs its declared typed outcome inputs and authenticated custody.
The consuming contract determines any scientific qualification requirement.

## Author and prove without contact

Use an adapter-owned authoring command only where the selected route guide documents one.
The installed authoring paths cover the reactor prefix, numerical RC ladder, analytic electron gas, synthetic lattice-pairing method and exposed six-matrix response routes.
Native diagnostics, input preflights and deferred integrations keep their stated boundaries. They do not gain an authoring path from this lifecycle.

For an authoring route, supply its strict checked-in input or a new input supported by that family's contract.
The command emits the documented typed study/candidate packet and its declared payloads and decoder proposals.
The normal engine separates the scientific `CampaignSpec`, the compiled `ProtocolRunPlan`, and the lowered `ProtocolExecutionPlan`.
Those records do not prove a task executed.
The [assigned reactor authoring walkthrough](../../programmes/foundations/measurement-and-response/workflows/reactor-response/authoring.md) describes the assignment profile and the proof before native contact.
Its fixed exposed profile is a development example.
The [RC numerical guide](../../programmes/foundations/measurement-and-response/workflows/rc-ladder-response/guide.md) gives the local model route.

Keep the target Git commit clean and fixed. Create an
`OperatorStorageProfile` with an external guarded mount, distinct artifact
and scratch namespaces and enough free space. The profile identifies storage
but grants no scientific or execution authority. Follow the proof or readiness handoff documented by the selected family guide. Where that guide uses `campaign
check-readiness`, the command takes the exact authoring file, each extension
payload and decoder, expected candidate, source closure, resource envelope
and prospective run ID. It resolves selected providers, runners, native input
identities, output and adjudication locators, resources and authority gates
without native effects. If an adapter or source contract gives a refusal, do not request an issue.

## Issue, execute, recover and reveal

For a genuinely new, unexposed and source-qualified roster, an accountable
operator supplies the required typed proposer attestation and separate
custody/publication authority to `campaign issue` and `campaign issue-extensions`. Scientific approval and execution authority are separate inputs to `campaign
assemble-package`. The issued graph is then compiled and run using
`campaign compile-plan` and `campaign run`. `campaign resume` recovers under the
same issued authority and immutable receipts.

A distinct reveal authorization
permits evaluator access and scientific adjudication. Before you make an evidence claim, examine actual native task receipts and the adjudication record. The [reactor operator walkthrough](../../programmes/foundations/measurement-and-response/workflows/reactor-response/operation.md) gives the complete
storage/trust setup, record constructors and returned-ID handoffs through
recovery. The [CLI reference](../reference/cli.md) gives the exact command options.

Neither a preissue proof nor a successful native diagnostic is an
issued run.

External or hardware routes require the operator's allowed source bytes,
calibration and access grant in the family's stated format. Their precontact
checks can validate a source or decoder without asserting instrument contact
or native truth. If the register describes a deferred integration, use only its advertised checked boundary.
A missing candidate, provider, scientific check or authentic input prevents complete experiment execution.
