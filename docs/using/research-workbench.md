# Use the local research workbench

SPDX-License-Identifier: CC-BY-4.0

The workbench opens registered investigations in **Current experiment**, **Results**
and **Knowledge**. Follow a question through its requirements, original findings,
recorded decision and remaining work. Knowledge offers programme and discipline
views over the same selected identities. No disk scan or scientific read runs
when you browse the collection.

**Tools** retains original-path inspection, workflows, invocations, inquiry,
knowledge exchange and composite programmes. Its **Design & run** view supports one bounded exposed RC wave through
copied-input preparation, authoring, execution and receipt recovery.
Use each selected scientific guide for its scientific design and prerequisites.

## Select an engine and storage

Use the [locked environment](environments.md) and the study's current
[retained-access selections](results-and-failures.md).
The selected engine must contain `empirical_lawhood.workbench.engine`.
An older installation can refuse this application contract while its original
CLI remains available. The launcher does not install or modify that engine.

Save the following operational document at an explicit input path.
Replace the example paths with the selected interpreter and operator profile.
The context ID is an application label. It is not a scientific identity.

```json
{
  "schema": "empirical-lawhood/application/contexts",
  "version": "1.0.0",
  "contexts": [
    {
      "schema": "empirical-lawhood/application/context",
      "version": "1.0.0",
      "value": {
        "context_id": "retained.study",
        "label": "Original retained study",
        "python_executable": "/absolute/selected-environment/bin/python",
        "operator_profile": "/absolute/retained-access-profile.json",
        "maximum_parallel_tasks": 4
      }
    }
  ]
}
```

For relocated evidence, add `artifact_root_contract` with the current retained
root contract. Its physical policy must match the operator profile.
For a programme that has prospective phases, also select `project_root`,
`catalog_relative_path` and `approval_checker_trust` as required by its guide.
The project root must belong to the selected engine.
Use `read_access_paths` for the selected original protected-access locators.
These paths supply no authority by themselves.
The exposed RC and SCI02-D views do not accept protected-access selections.

For the RC lifecycle, select `project_root`, `input_root`, `invocation_root` and
`progress_root` in the context. Create those operational directories explicitly
on the selected external volume. Keep them separate from closed scientific
packages. `input_root` holds copied editable inputs and new canonical files.
`invocation_root` holds durable handles; `progress_root` holds advisory updates.
The selected worker count must fit the operator profile. Each engine process
starts with one numerical thread per worker before numerical imports.

For the explorer, also select `collection_path`, an absolute operational JSON
path beneath the profile's scientific scratch root. Select `operational_profile`
when that writable operational root differs from the original study's custody
profile. For a new exposed local example, use the profile returned by the
[public workspace constructor](../v1.0/define-investigation.md#use-the-application-api).
For an existing study, select its actual authenticated profile and explicit paths.
Keep original scientific profiles and relocated root contracts unchanged.
The optional `observation_root` selects imported remote observations below the
same guarded scratch root. [Remote observation](observing-remote-work.md) describes
its separate collector and return procedure.

Several contexts can use different installations and retained roots.
Switching context clears the current view. The broker starts each engine in a
separate process and never changes a live Python import path.

## Open the local session

Select an available mounted volume, a new invocation directory beneath it and
the context document. Replace every example path with the actual selected volume
and directories:

```sh
uv run --no-sync python -m empirical_lawhood.workbench.broker \
  --contexts /absolute/selected-volume/el-workbench/my-study/contexts.json \
  --required-mount /absolute/selected-volume \
  --output-dir /absolute/selected-volume/el-workbench/my-study/session-01
```

Open the printed local URL. Its fragment supplies the session key.
The browser removes that fragment and sends the key in a request header.
The service binds only `127.0.0.1`. It serves no arbitrary local files.
Use `--port` to select a specific local port.
Press Ctrl+C in the launcher terminal to close this inspection session.
This closes the broker. An entered durable invocation continues independently.

The main page lists the selected collection. Open a question for a fresh owning
read. Current experiment has Question, Finding, Evidence and Method inspection
depths, a diagram and an equivalent outline. Local expansion and lens changes
reuse the opened response; exact record, companion and method inspection repeat
the current owning checks. The diagram shows at most sixteen nodes and thirty-two
edges, with continuation or outline views for the complete census.

The Rubisco conditional-root view separates completed analytical tasks,
numerical reconstruction, unresolved physical conditions and unevaluable
biological validity. Its separately selected HOLD, work account, acquisition
attachments, standalone assessment and contribution retain their own identities.
Empty realizations supply no endpoint ratios. Historical runtime observations
are distinct from the reader installation and any future worker.

The separate **Paired preparation and formation response** presentation opens an authored prefix,
continued prefix, response-point, independent-analysis or destination-supply wave.
Select `rubisco.preparation-response`, revision `1.0.0`, and the original directory returned by the workflow.
All six questions stay visible before acquisition. Unentered, unavailable and adverse
findings retain their own states, signed quantities, uncertainty and complete denominators:
four nested positions, zero biological replicates, four original materials, 32 sites
and 384 starting hypotheses. Opening a question's exact record repeats the original
reader's current checks. The Method tab describes the local protocol and its declared
source; it supplies no missing observation.

Use the [preparation-response procedure](../../programmes/biology/photosynthesis/workflows/rubisco-response/preparation-response-v1.md)
for configuration, original-input preparation, `continue-prefix`, inquiry decisions,
execution, independent analysis and contribution admission. The workbench reads the
returned wave. A completed software task or displayed safe checkpoint does not answer
the molecular questions or establish kinetic admission. The original conditional-root
view retains its own unresolved requirements and historical decision.

Costs distinguish measured disjoint work, actual billing, prospective scenarios
and a matched conventional comparison. Unknown spend and unavailable savings
remain explicit. Historical force-call scopes can overlap and are not summed.

Knowledge group membership and informing links are editorial. Opening an original
also exposes its source-backed requirement relationships, operation connections
and unselected proposals. Certificate verification and destination admission use
**Tools → Knowledge & exchange**. A collection does not enumerate unseen imports
or later corrections.

For advanced original-path opening, choose **Tools**, then select a context and
object type, enter the directory returned by its workflow and choose **Open result**.
Older contexts keep these routes even when they lack explorer operations.

| View | Meaning |
|---|---|
| Execution | Original assigned tasks and attempts. Scientific reconstruction remains deferred. |
| Question & relationships | For a bounded RC wave, the original requirements, connections and separate execution dependencies. |
| Findings | An explicit bounded RC scientific read. Each assessment keeps its identity, revision, disposition and reasons. |
| SCI02-D recorded findings | Original products, arrays and completed native custody. Independent numerical reconstruction remains deferred. |
| Analysis package | The authenticated completion and complete member census of an exposed retained analysis. |
| Matrix programme | The owning retained programme read with scientific reconstruction off. Current custody and access still apply. |
| Registered findings | An installed bounded domain presentation over its original scientific reader. Unsupported panel revisions retain an identifiable generic view. |
| Continuing source history | Original exposed session, actor generations and selected event windows. Lifecycle closure and event completeness remain separate. |
| Finite source operation | One original request, prepared inputs, possible contact and effect receipt. Unknown effects remain unknown. |
| Provenance | Original source, plan, packet and dependency identities supplied by the owning reader. |

The RC view accepts at most sixteen registered RC operations and a four MiB
draft. It does not extend to an arbitrary large scientific reconstruction.
The analysis preview accepts selected JSON or text members up to its declared
limit. It does not execute retained HTML.
Unsupported actions return an explicit reason.

For **Registered findings**, select an installed presentation and the original authoring directory.
Select `invocation_root` and `progress_root` for its durable read.
The mass-balance view keeps exact kg values and missing observations.
The assigned-opportunity view keeps dependence roots, nested views, stopping rules and complete opportunity counts.
Its procedure, instance, admission and joined-use dispositions remain separate.
These views start no scientific workers and supply no qualification.
The separate Rubisco conditional-root and preparation-response views retain their own original scopes as described above.
The [presentation contract](../development/workbench-presentations.md) defines registration and revision fallback.

For **Continuing source history**, select the returned original session directory and explicit event and boundary windows.
For **Finite source operation**, also supply its original request ID.
Both views require the selected invocation and progress roots.
The [source guide](../development/continuing-sources.md#inspect-exposed-historical-records-in-the-workbench) gives their exact limits.

Use **Knowledge & exchange** to inspect original certificates and local stores.
The [exchange guide](../development/portable-knowledge-stores.md#workbench-inspection-and-reviewed-exchange) gives the context selections and review procedure.
Discovery, original assessment, current verification and consumer admission remain separate.
Review binds the complete selected transfer and destination. Apply repeats current owning checks.
Unseen corrections remain unknown. Original adverse and unevaluable findings remain available.
Historical actor records grant no current lease or permission to repeat an effect.

Execution success does not imply scientific support.
A filter changes the displayed rows, while the complete denominator stays
visible. Decimal values and large integers retain exact string representations.
The record inspector shows the original schema and revision where supplied.
It performs a fresh owning read before opening the selected record.

For **SCI02-D retained wave**, select `invocation_root` and `progress_root` on the
external volume. Open its execution records first. Choose **Recorded findings**
to inspect the original root banks, uncertainty, adverse findings and molecular
limits. Each such read authenticates original source, receipts, predecessors,
array custody and completed native outputs. It does not reconstruct forces,
transitions or the fit. This authenticated view can also take several minutes.
Finite binary64 array values use exact Decimal representations in the transport.
Nonfinite array values retain their IEEE bits in `binary64_bits` fields.
Complete receipts alone supply no historical publication
failure log or committed inquiry decision.

Choose **Reconstruct & export full report** for the full independent scientific
reader. This explicit durable action can take several minutes. It downloads the
complete report without acquiring another trajectory. Filters, record inspection
and navigation do not select that action. The recorded view and downloaded report
retain separate read scopes. Their qualification and molecular limits remain
unchanged. Use the [SCI02-D guide](../../programmes/foundations/emergent-structure/workflows/matrix-equilibrium-bridge/guide.md)
for the original procedure and recovery rules.

## Prepare and run a bounded RC wave

Follow the [recursive inquiry guide](recursive-inquiry.md) to select the input.
The workbench accepts copied RC text up to 128 KiB and at most sixteen registered
RC operations. A larger design needs its owning command or a separately accepted
application route. The browser does not construct scientific task rosters.

1. Open **Design & run**, enter a copied input file and choose **Open copied input**.
   Edit the exact text, including Decimal tags, units and source references.
2. Choose **Validate current edits**. Invalid text remains in the editor.
   Validation creates no files, native work or scientific authority.
3. Select a new canonical file and choose **Prepare new canonical file**.
   The original file is preserved. Existing files and changed original bytes refuse.
4. Choose **Review prepared design**. Inspect its complete operation and requirement
   counts, unresolved premises, worker selection and current source identity.
5. Select a new authoring directory and choose **Author reviewed wave**.
   The owner rechecks the exact reviewed input and producing implementation.
   Use the returned authoring path and packet digest.
6. Choose **Run selected wave**. For an existing wave, first enter its original
   directory and choose **Inspect authored wave**. **Recover original receipts**
   uses the same original recovery owner; it does not force replay of uncertain work.

Changing editable text invalidates its preparation selection. Authoring performs
no native acquisition. Native resource and source admission remain at execution
entry. Execution completion and scientific support remain separate.
Interruption is unavailable in this browser route. Use the selected guide's
supported operational controls when needed.

**Open original results** reopens the authored object through its owning reader.
**Export complete report** performs an explicit fresh scientific read of the
bounded RC wave and downloads its complete JSON report. The report retains its
original exposed development scope; it is not a contribution or qualification.

## Inspect and commit an inquiry

Use **Inquiry & successors** with the context's selected input root and original
custody profile. The [inquiry procedure](recursive-inquiry.md#retain-an-inquiry-decision)
owns the canonical request, decision rights, input origins and registered builders.
Select that existing request and a new decision directory, then choose **Review
inquiry decision**. The review shows the actual selected action, alternatives,
unresolved conditions, cutoffs, work and costs. It creates no decision package.
**Commit reviewed decision** repeats the original policy and authority checks
and retains the exact reviewed packet. Editing a selection invalidates the review.

Select the returned decision directory for successor authoring. Supply the
canonical origins and either the initial draft or completed supplier directory.
The supplier route uses its installed builder and original contribution. Bind
external inputs explicitly with one `INPUT_ID=/absolute/path` per line. Inputs
must be beneath the selected input root; this view accepts at most sixteen
bindings and 128 KiB per copied input. Review the new authoring destination,
then choose **Author reviewed successor**. No scientific task enters through
these controls. Use the owning inquiry run procedure for admitted execution.

Open an original decision to inspect its complete retained records. Select its
original successor directory to authenticate both directions of the admission.
The returned links use the original decision path and exact packet identities;
the workbench does not infer a chain from narrative history. **Read as historical
archive** preserves archived bytes without current admission. Current successor
inspection repeats the original decision, source, origins and work checks.
A HOLD or STOP cannot authorize a successor. Current completed-work reuse,
human-directed forks and run/recovery remain with their existing documented APIs.

## Review a composite programme

Use **Composite programmes** with the original programme profile. **Inspect
original programme** delegates to its registered reader with reconstruction off.
Its component records, frontier, missing work and adverse results keep their
original scope. The context's component request supplies any required current
access. A damaged descriptor refuses before any single-campaign route.

For a new programme, follow the selected guide to obtain the copied
specification, canonical scientific input selection, implementation snapshot and
optional scientific protocol. Select their absolute paths below the context's
input root, the environment ID and a fresh programme directory. Each selected
control file is bounded to 1 MiB. **Review programme preparation** uses the
existing input and preparation owners. **Author reviewed programme** repeats
that preparation and enters the original authoring service; it does not run a
scientific task.

To execute or recover, select the original programme directory, the operation
and its copied component request. An omitted request uses the context's request.
**Review programme operation** binds the descriptor, current context and request
bytes without invoking an unconfirmed run. The apply button repeats that review
before entering the selected owner. Component source, input, resource, execution
and reveal requirements remain necessary. Editing a selection clears the review.
The returned report and original paths remain available in the invocation.

## Current access and invocation records

Each application request reopens its selected custody and current access.
The broker stores no scientific response cache or access verdict.
An access refusal clears the browser's prior result and inspector.
An inactive tab also clears its retained view. Open the object again for a
current read.

The broker session directory contains context and engine observations for that
session. Its short reads retain entry and return metadata. The selected
`invocation_root` contains each durable dispatch intent, exclusive entry,
operational attempt and return metadata when available.
Return metadata includes response size, digest, status and elapsed time.
These files contain no scientific response body or session key. Unsaved text is bound by its exact digest; arbitrary edits are not copied into general logs.
They are operational diagnostics, not scientific receipts.

Only one durable invocation can enter in each context. Repeating an identical durable
request returns its original handle; changing its operands refuses. An entry
without a return does not establish completion. Inspect the original scientific
receipts before using their documented recovery procedure.

Open **Invocations** to inspect a handle after a lost reply or broker restart.
If the local address changed, enter the complete original handle explicitly.
Returned paths and packet/run bindings remain in the original metadata.
Scientific response bodies are not saved by the broker. Reopen an original
result for a fresh owning read.

Ordinary read transport has a finite process limit. Matrix frontier inspection,
SCI02-D reads, RC effects and full RC report export use detached durable workers. Their
one-hour response-delivery limit closes the pipe without killing the worker
or introducing a scientific deadline. A lost response never triggers a retry.
An unresolved invocation blocks further durable dispatch in that context.
`INVOCATION_DELIVERY_UNAVAILABLE` means the reply was not delivered; inspect
the original handle before selecting a recovery action. The worker can still
be running. An export refusal clears the previous retained findings.

Advisory progress uses the shared [operational-progress.v2 record](progress.md)
and a separate invocation/sequence binding. The same phase/workflow counters,
elapsed times and bounded step summaries feed the CLI and application. Nested
operations share one heartbeat; observed task identities are exposed, and absent
identities remain explicitly unknown. A quiet feed becomes stale, never completed.
The cards separate current-phase counts from whole-workflow counts.
Unknown totals have no percentage.
Active and uncertain handles refresh every two seconds while the view is visible.
Transient failures retain the last report and permit another state request.
Hidden and terminal views stop automatic polling.
Original execution receipts own completion.

## Use the same request from a terminal

Save one context object from the `contexts` array in a separate file.
Save a request with the same context ID:

```json
{
  "schema": "empirical-lawhood/application/request",
  "version": "1.0.0",
  "request_id": "inspect.original.01",
  "context_id": "retained.study",
  "operation": "recursive.execution",
  "parameters": {
    "directory": "/absolute/original-authoring-directory",
    "limit": 50
  }
}
```

```sh
uv run --no-sync python -m empirical_lawhood.workbench.command \
  --context /absolute/selected-context.json \
  --request /absolute/selected-request.json
```

This terminal client uses the same typed request, selected engine and result
envelope. Add `--required-mount /absolute/selected-volume` for a durable request. It prints
the accepted handle to stderr before waiting for the original response. Replace
`--request` with `--handle ORIGINAL_HANDLE` to inspect that handle without dispatch.
The existing RC author, run and result commands keep their options and original
report formats while using the shared selected-route application services.
Other recursive designs retain their existing owning command paths.
See [results and failures](results-and-failures.md) for original-result commands.

## Register an investigation

Human and agent operators use the same `collection.register` application service.
Registration writes operational navigation metadata, not a scientific package.
Save a `run-selection` document with the following fields under `value`:

| Field | Selection |
|---|---|
| `selection_id`, `investigation_id`, `context_id` | Stable operational labels; several waves can share one investigation. |
| `label`, `question` | Bounded operator text, displayed as unverified until an original read. |
| `identity` | Exact returned `ObjectIdentity`, or `null` before a result is selected. Never invent one. |
| `readers` | One to sixteen original locators: `operation`, absolute `directory`, optional `context_id` and exact `expected_identity`. A presentation also selects `panel_id` and `panel_version`; `analysis.member` selects `member`. |
| `classification` | `programmes` and `disciplines` arrays of `{id,label}`, and an editorial `source` pin `{path,sha256}`. Empty arrays mean unclassified. |
| `companions` | Explicit original `inquiry`, `work-cost`, `contribution` or `assessment` directory and identity; or separately pinned audit `attachment` roles. |
| `stages`, `deployment`, `links` | `[]`, `null`, `[]` when absent. Remote stages and deployment use the observation guide. Editorial links carry `target`, `kind`, `label`, `source`; kind is `INFORMING_REFERENCE` or `CLASSIFICATION`. |

The envelope is `{"schema":"empirical-lawhood/application/run-selection",`
`"version":"1.0.0","value":{...}}`. Copy all scientific identities and locators
from the owning workflow's returned records. The collection accepts 256 entries
and one MiB. It preserves equal labels as distinct objects, aliases a repeated
original identity and rejects substitutions of an existing locator or deployment.

First issue `collection.list`. Then send `collection.register` with `text` equal
to the selection file's exact JSON text, and `expected_collection_sha256` equal
to the listing's `summary.collection_sha256` when non-null. An intervening edit
refuses; read the current selection before deciding the next update. The same
request works through `workbench.command` above or `execute_application` with
the selected `ApplicationContext`. Retain each returned request and response in
your chosen operational input/output directories.

To add local returned custody, resubmit the original selection with another
reader appended. Preserve all previous readers, companions and deployment pins.
The **Open returned original** control selects among those registered readers.
The independent read still authenticates original custody and scientific scope.
Companions use the entry's registered context. An alternate reader in a different
context does not acquire that context's companion access; open the returned
reader in the registered context to inspect its selected companions.
For a standalone Rubisco assessment, its companion additionally supplies the
complete `sources` array: each original source's `identity`, canonical external
root `contract` and `relative_path`. The original export reader verifies that
census and reconstructs the same root result; a checksum attachment cannot replace it.

Browser preferences retain only navigation choices. Paths, scientific bodies and
access decisions are not stored as preferences or placed in shareable URLs.
After a restart or inactive tab, open an original again for its current read.

For implementation boundaries and verification scope, read the
[architecture decision](../development/workbench-architecture.md).
