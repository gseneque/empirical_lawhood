# Read a result or recover a failure

SPDX-License-Identifier: CC-BY-4.0

This guide explains development reports, operational attempts and issued scientific outcomes.
It keeps their identities and evidence limits distinct.
Start with the readable report, then inspect its exact inputs and outcome pointers.

## Find the output

The [workflow catalogue](../reference/workflows.md) identifies each task's commands, input roles and first missing prerequisite.
`workflow show ID --format json` reports static facts. It inspects no environment, source or authority.
The [CLI reference](../reference/cli.md) owns exact effects, options and exits.

| Product | Meaning and next action |
|---|---|
| Reactor example `report.md` | First readable summary. The paired contrasts describe exposed development units. |
| Example `report.json` and `panel.json` | Exact summary and canonical native episodes. Arms and numerical views remain nested within five independent units. |
| Development `report.json` | The original command's successful JSON output. Interpret its actual units, clocks and denominator using the family guide. |
| Development `report.md` | Readable operational state, exit and stage, with links to the actual JSON quantities. It supplies no qualification. |
| `invocation.json`, `diagnostics.jsonl`, `failure.json` | Operational context and diagnostics for an explicitly retained attempt. They do not replace scientific receipts. |
| Candidate authoring directory | Family-specific strict records, pure candidate/plan projections and source/resource contracts. Compilation is not issue or execution. |
| Issued manifest, artifacts, receipts and adjudication | Primary recorded acts and outcome identities under separate source, custody and authority gates. |
| Local catalog | Rebuildable metadata projection. Its absence is not absence of primary receipts. |

Keep operational output outside the source tree, except for the documented disposable demo destination.
A retained attempt is a reproduction/debugging aid, not a fresh independent scientific unit.
Completed development reads through `campaign recursive-development-result`,
`campaign rc-chain-result`, `campaign matrix-geometry-result` and
`campaign selected-events-result` use the installed package and selected storage.
Supply `--operator-profile`; when retained materializations use a different storage identity,
also supply their `--artifact-root-contract` with matching physical storage policy.
These readers accept a read-only profile without requiring `--project-root`, Git or the producing checkout.

`campaign experiment-read` uses the same boundary for development-only results.
A programme containing prospective phases also constructs the ordinary application API.
Select its authenticated reader source with `--project-root`, the retained operator profile,
and the actual `--catalog-relative-path` beneath that profile's scientific scratch.
Installed readers select their matching source distribution; they do not claim to be the original producer.
Omitting the catalog option selects the legacy repository catalog and therefore requires a Git worktree.
Keep required trust and current protected access selections.
Reading does not acquire, issue or grant new access.
Authoring, execution and recovery retain their own source and effect admission.

The producing generic-validator stamp remains part of the original artifact
identity. Current readers validate bytes with the installed format and semantic
contracts. They require no producing validator source or predecessor-hash list.
A changed stamp still changes the committed manifest identity. Unsupported
formats, corrupt members and substituted publications retain their refusals.

The [operational verification mode](configuration.md#operational-artifact-verification)
defaults to `reduced` and appears in each retained invocation report.
Reduced intermediate checkpoints use metadata and current access after first-use authentication.
Full publication, worker-delivery and final read checks remain required.
Select `--artifact-verification strict` before the command group for full intermediate hashing.
Same-size changes with preserved timestamps can escape a reduced intermediate checkpoint.
Persistent changes still refuse at the final read boundary.

Returned JSON reports retain the complete encoded report, including programme
source and receipt censuses. Export uses the report's exact encoded byte allocation
and records its byte count and SHA-256; a separate cohort-size ceiling does not
reject completed work. Storage or publication failure retains `EXPORT_FAILED`
and the completed-operation flag. Inspect primary custody before any rerun.

With an explicit operator profile, independent snapshot byte checks use up to
the selected worker count. Current access callbacks remain serialized and live;
thread workers inherit the current read scope. Nested verification stays serial,
and active reads join before an error escapes. Complete final byte checks and
current-access checks remain mandatory. Publication and journals keep
their ordinary atomic coordination. This parallelism does not add native task
attempts or numerical threads to a worker.

Artifact publication uses bounded temporary filenames independently of the
published target name. Long, valid receipt identities retain their exact final
paths and bytes; staging, atomic publication and interrupted replay use the same
custody checks.

New task receipts keep publication controls beneath their individual task's
receipt directory. This avoids collecting ordinary and nested receipt markers
in one run-wide directory, whose entry capacity can be exhausted even when the
volume has free space. Existing receipt payloads, paths, manifests and recorded
publication scopes retain their original custody. Read the original marker
binding when recovering an older or interrupted publication; relocation or a
different control layout does not establish completion.

Recursive waves with multiple portable parents retain a complete
`parent-closures.json` census. Readout, execution and contribution export
authenticate every original parent receipt and transitive byte closure; missing
or substituted parents refuse before execution. Existing singleton waves retain
their original `parent-closure.json` format. Shared ancestors keep their original
receipts and scientific identities: relocation or another incoming edge does not
create a new attempt, cost event or independent unit.

Recursive result readers support `documents`, `references` and `compact`
formats. `references` retains the typed scientific read but presents exact
product references. `compact` authenticates all retained bytes and the complete
operational census; it does not decode scientific products or project connection
assessments. Read its explicit `typed_product_validation`,
`connection_assessment_projection` and `scientific_completion` fields before
using it as evidence. Custody authentication alone is not scientific assessment.

For a completed recursive development wave, use the existing read-only custody
verifier with the selected storage profile and returned authoring directory:

```sh
uv run --no-sync empirical-lawhood \
  --operator-profile /absolute/operator-profile.json \
  campaign recursive-development-result \
  --authoring-dir /absolute/returned-authoring-directory \
  --terminal-product-format compact
```

This command does not resume tasks. Issued and composite experiments retain
their guide's `experiment-read` and current reveal selections; a metadata-only
partial report is not a substitute for complete byte or scientific validation.

Matrix programme advancement uses a separate `EXECUTION_RECORDS` observation
for E1/E2/TRAIN. It authenticates the original plan, terminal and complete frozen
attempt/receipt census, including unused slots, without opening scientific
payloads. It therefore reports `DEFERRED_TO_FULL_READ`. The outer
`OPERATIONAL_ADVANCE` report can reach `OPERATIONS_COMPLETE`; only an explicit
full programme read or export validates every observed scientific result.
Outcome-dependent consumers still own their required full reads. Immediate
child scientific reports are used once, and advancement performs no final
whole-programme replay or persistent verification caching.

The [Matrix source-continuation workflow](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#continue-after-a-source-change-before-train)
can preserve completed E1/E2 across a source change before any TRAIN execution.

also defines explicit reconstruction of retained TRAIN banks from their complete

claiming a completed numerical replay. The current installation reads the
original producer's export and retains its provenance. New authoring and native

The [entered-E3 continuation](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#continue-after-e3-prefixes-and-model-freeze)
preserves an original blocked or failed run after all prefixes, physical forecasts,

Its reader authenticates the complete partial receipt and native-event custody,
original source and current reveal access. A separate run adopts the exact

The original terminal remains unchanged. Full scientific reads report the

An exhausted PURE `matrix-e3-configured-protected.retained-fit` adoption has a

reuses successful receipts under their actual producing source, and admits one
additional adoption attempt. Previously blocked tasks receive their first
execution through ordinary dependencies. The old plan, maximum attempts, terminal,
receipts and resource journal remain unchanged. A separate journal retains the
entire old prefix and an explicit PURE repair event. Native, unknown, reserved
and already successful failed-task selections refuse this transition. A failed
repair may continue under a separately installed corrected controller through
the same command; committed PURE outputs must match the original model bytes.
The failed wave remains immutable. Repeating the same controller selection

An exhausted PURE development calculation can use the separate

It requires a settled `BLOCKED` terminal and successful receipts for every original native task.
The public `--repair-development-output-bytes` selection raises only the refused calculations' output allowance.

An additional recovery index binds one new attempt per refused calculation and first execution of dependency-blocked PURE work.
Both installed sources and the original worker environment are authenticated.
The original scientific source, dependency lock and current input-access checks remain mandatory.
Unknown contact and other failure classes refuse this transition.
Repeated selection resumes the same repair and supplies no further attempt or native acquisition authority.
Result reads retain the original terminal identity beside the additional repair terminal.

to select a new installation for later unentered phases.
The continuation preserves both E4 terminals and all completed phase bindings. It cannot reacquire original E4 work.

An interrupted development graph with completed receipts and an actual PURE output refusal can use
the explicit [controller repair](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#resume-interrupted-development-with-a-repaired-controller).
It preserves the complete original control census, including an absent terminal after a drained interruption.
The original frozen worker executes unfinished tasks. Only native tasks with no prior contact may enter.
Uncertain contacts, native failures, unreceipted outputs and changed controls refuse recovery.
The selected PURE output allowance also covers unfinished calculations of the same refused capability.
The separate repair index and result readout retain all original successes and refused attempts.
Current source, resource, execution and input-access prerequisites remain mandatory.

A controller-only interruption stops new dispatch while admitted tasks drain.
The scheduler must continue renewing their same owned leases during that wait;
worker threads cannot renew the coordinator's leases. Current native-entry
permission and lease ownership still apply at every later leaf. A drained process
exit does not establish completed task receipts. Inspect the actual nested
contact, return and output census before selecting recovery. Missing outputs or
an uncertain contact cannot be repaired by repeating the original native attempt.

The separate [incomplete-native proposal](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#prepare-a-separate-incomplete-native-continuation-proposal)
records exact unfinished invocations for review without recovery or dispatch.
It preserves the original complete denominator, successful receipts and `BEGUN` or `UNKNOWN_COMPLETION` states.
Known returns, partial products, changed controls and missing current access refuse candidate preparation.
Its `PREPARED_REVIEW_REQUIRED` result grants no execution and creates no additional independent observations.
The [separate execution owner](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#select-a-separate-native-continuation)
requires a distinct explicit selection before it can publish or dispatch its additional attempt index.
Default validation starts no work.
Its result preserves original incomplete attempts beside the later completion or refusal.
Separate native storage preserves the frozen worker's receipt identifiers and exact scientific operands.
An additional attempt creates no independent observation and establishes no nonentry fact about the original attempt.
The proposal does not change the ordinary prohibition on replaying uncertain native work.

The explicit partial compact read retains completed receipts before terminal
publication or after a blocked or failed terminal stops dispatch.
An assigned task without completion custody reports
`NO_COMPLETION_RECEIPT` and `ENTRY_OR_PROCESS_STATE_NOT_INFERRED`. This read
does not resume or repeat a task. Inspect actual process state and native contact
before choosing a continuation. Received native output prefixes remain separate
from complete scientific outputs, even when their retained bytes are authentic.

A recursive run that returns a blocked or failed scheduler result uses this
compact report. It retains authenticated terminal custody when present and
does not invoke subsequent scientific production. An incomplete blocked

with `operational_terminal: ABSENT`, retaining actual attempts and identifying
missing completion records. Successful execution retains the selected report
format and its full scientific read.

Completed native-output reads and retained Matrix readers require the original
nested completion receipts. They inspect custody without publishing a missing
receipt. A durable known return without that receipt remains incomplete until
explicit current-run recovery finalizes its authenticated publication. Reading
it grants no new native entry or retry authority.

Recovery that needs unentered native work retains an obstruction. A refusal by
the completed-only producer is not pending publication, and waiting for a lease
to expire cannot supply the missing native result. Legitimate nonentry results
can still complete their original publication without entering native work.

Raw matrix products remain exact NPZ artifacts with canonical array manifests.
The generic result reader reports their custody references. Exact scientific

no new qualification.

exports complete phase readouts and original scientific-product references

## Monitor an operation

The shared `campaign experiment-*` commands accept an optional `--progress-file`.
Select a new file with an existing parent, outside scientific and operational attempt packages.
Keep it outside any explicit `--output-root` selection as well.
For example, add `--progress-file /absolute/operational/e3-progress.json` to the selected experiment command.
Read that file from another terminal:

```sh
uv run --no-sync empirical-lawhood progress --file /absolute/operational/e3-progress.json
uv run --no-sync empirical-lawhood progress --file /absolute/operational/e3-progress.json --json
```

The view shows the current phase, processed items, known total, percentage and operational failures.
Unknown totals have no percentage. Each phase has its own denominator. There is no estimated overall percentage.
Updates replace the advisory JSON atomically, normally at most once per second.
Phase changes and terminal states force an update. A long item can leave the timestamp unchanged until its next counter update.
Use a terminal monitor such as `watch` to repeat the read command.

The status `RETURNED` means the invocation returned. A blocked return can have an incomplete task count.
Task counts include authenticated recovered successes and actual terminal failures. Unattempted blocked tasks remain incomplete.
A failed status write disables further updates and reports one stderr warning. The underlying operation continues.
An interrupted process can leave a stale `RUNNING` snapshot. The view does not infer process liveness.
Use actual processes and receipt custody to determine completion and recovery.

Python callers can use the same reporter around an existing operation:

```python
from pathlib import Path
from empirical_lawhood.infrastructure.progress import JsonProgressReporter

with JsonProgressReporter(Path("/absolute/operational/job-progress.json"), operation="job") as progress:
    progress.update(phase="validate_inputs", done=0, total=len(inputs))
    for done, item in enumerate(inputs, 1):
        validate(item)
        progress.update(phase="validate_inputs", done=done, total=len(inputs))
```

Installed preparation, input publication, artifact validation and execution hooks use that invocation's reporter.
The reporter retains no scientific values, authority or completion evidence. Scientific results retain their existing readers and receipts.
Omitting the option creates no progress file. An already running job retains its original implementation.

## Retain a development attempt

Participating stdout diagnostics accept an explicit new `--output-dir`.
For example, after [validating and preparing a copied RC model](configuration.md):

```sh
uv run --no-sync empirical-lawhood campaign rc-ladder-native-check \
  --config /absolute/development/rc-model.json \
  --output-dir /absolute/development/rc-ladder-response/attempt-001
```

The default stdout JSON and exit convention remain unchanged when the export option is omitted.
Progress and output-location messages use stderr. Raw stdout/stderr redirection remains possible,
but an empty captured stdout file is not a successful report.

The writer retains invocation context and bounded diagnostics.
`invocation.json` records `operation`, `state`, `exit_code`, `stage`, `last_completed_stage`,
`operation_completed`, `native_contact`, input/product identities and observed `runtime`.
Treat unknown contact or incomplete finalization as unknown, not as no contact.
`operation_reported_complete` records a returned command report, not verified native contact or scientific completion.
A direct issued preview with `WRITE_CONFIRMATION_REQUIRED` and `confirmed=false` records `native_contact=none`.
Its attempt can report `SUCCEEDED` while the returned API operation reports `BLOCKED`.
Read that API status and its reason codes before selecting the next operation.
`failure.json` normally records `exception_type`, `cause_types`, `stage`, a sanitized `diagnostic` and `next_action`.
It does not store arbitrary exception text, stack locals or hidden outcomes. A secondary export failure can retain a fuller operational failure record.
Exact returned scientific quantities remain in the original route report.
A successful computation exports its actual `report.json` and readable `report.md`.
A failed invocation exports `failure.json` when its selected destination is usable.
No success-looking `report.json` is invented for failure.
A bounded `input.json` (or supported `input.yaml`/`input.yml`) snapshot is present only for permitted small development inputs.
Large, guarded, held or authority-bearing inputs remain references/digests under their owning contracts.

Closed authoring bundles and the reactor demo retain their existing `--output-dir` products.
Use their separate `--attempt-dir` for operational records, with disjoint destinations.
Do not add operational sidecars to a closed, hash-bound scientific package.
Each family's existing empty-directory, nonexistence and partial-export rules remain in its guide.

### Recognise an actual retained directory

For the RC diagnostic above, a successfully exported attempt has this layout:

```text
attempt-001/
├── invocation.json       operation, input identities, contact and final state
├── diagnostics.jsonl     bounded progress and stage events
├── input.json            permitted small RC config snapshot for this command
├── report.json           the diagnostic's actual returned numerical quantities
└── report.md             readable operational state and links to those quantities
```

The snapshot contains the copied development model.
It contains no held or protected source.
Read `report.json` with the [RC field guide](../../programmes/foundations/measurement-and-response/workflows/rc-ladder-response/guide.md#read-results-and-failures).
Voltages and solver differences are in V.
Boundary currents are in A.
Both solvers describe one model unit.

Exit 0 means that this diagnostic returned.
It does not issue a campaign or qualify a physical board.
A refused RC invocation exits 2.
If retention succeeds, its directory contains `invocation.json`, `diagnostics.jsonl`, `failure.json` and `report.md`.
`input.json` exists only if a permitted snapshot was read.
A refused invocation has no successful `report.json`.

An interrupted or failed export can leave only some of these files.
Inspect the actual final state.
Inspect completion and native contact before another operation.
Other commands retain their own products.
A closed authoring `--output-dir` or analysis `--output` is separate from its optional operational `--attempt-dir`.

| What you see | What to inspect next |
|---|---|
| Success report and final `SUCCEEDED` attempt | Read the family's quantities, units, independent denominator and scientific ceiling. Support and admission remain separate. |
| Invalid copied input or exit 2 refusal | Read the terminal refused field. Read the bounded failure/stage record. Repair the editable copy. Validate it. Select a new documented attempt path. |
| Destination refusal | Read that command's directory rules. Preserve occupied or partial products. A refused destination can retain no durable attempt. |
| Missing terminal record or interrupted export | Preserve genuine partial bytes. Determine completion and contact before further work. Missing finalization does not prove no native contact. |
| Saved analysis without completion publication | Treat it as incomplete under the family contract. Do not present its report as authenticated completion. |
| Reveal barrier | Obtain the separately authorized reveal. Use receipt recovery with the same identities. Do not repeat completed acquisition. |
| Valid negative or unevaluable scientific result | Retain the full census and declared disposition. An operational retry cannot select a different scientific result. |
| Completed doctor with warnings | Inspect availability and version fields. Select the guide's environment before native work. Diagnostic completion is not scientific readiness. |

For a prepared worker, the native no-progress interval starts after parent
admission permits execution. Process startup and source/input checks do not
count as native progress or consume that interval. The campaign elapsed limit,
attempt lease and non-time resource limits retain their separate checks.
A qualified stall retains its operational failure even when retries are forbidden.
A new reservation still requires its declared retry reason and remaining budget.

For a refused issued Matrix child operation, the programme report retains the
original API result under `dependencies[].operation_result`. It does not request
a complete scientific read from that refused operation.

## Work through an RC result and refusal

The [recursive inquiry result](recursive-inquiry.md) retains
the complete selected task census, exact phase products, producing source/runtime,
completion receipts and separate requirement supply assessments. A completed
assessment task can report `FALSIFIED`, `REFUSED`, `UNEVALUABLE` or `UNSUPPORTED`.
Its software completion does not turn that finding into scientific support.

A terminal can also retain retryable blocks that occurred before a worker
attempt, including several blocks before an explicit resume. Their exact task,
block identity and operational order belong to the authenticated terminal.
When no separate event exists, the operational census reports
`MISSING_TERMINAL_PRIMARY_NONATTEMPT` and `recovery_event: null`. This records
the observation without creating an executable attempt, a completion receipt
or Native retry authority. Entered attempts still require their original exact
recovery events and successful receipts.

RC phase products retain all ten observation variants and thirteen arm slots per
assigned preparation. Their final unit and complete-census summary project to the
original scientific records. Native contact markers record potential contact;
actual completed views are counted from the acquisition/delivery panels;
repeated reduction projections add no views. An unreceipted
contact blocks automatic repetition after interruption or catalog loss. A
completed receipt permits authentication and recovery without acquisition.
Concurrent launchers cannot share permission to enter a native worker: only
the new marker's atomic publisher may proceed. An existing or partial marker
retains the same conservative recovery rule.
For the recursive scheduler, a guarded run lock refuses a concurrent launch before it can schedule work or
publish a competing failure. If the first process dies, the lock releases;
its unreceipted contact still blocks automatic reacquisition.
An isolated interpreter also retains local operational process-start and observed
return witnesses in its explicitly selected working directory before publishing
them to the coordinator. These preserve the existing typed records and actual
PID/start-time join if the pipe is lost. They do not complete nested native units,
grant replay authority, or supply a return missing from an older attempt.
The direct RC and matrix custody helper also requires a newly created marker and
authenticates its exact readback. A losing publisher stops before calculation;
its identical marker bytes grant no additional native entry.

An exported contribution retains its scientific content, parent role, remaining
requirements and exact producing receipt closure. Procedure evidence is separate
from applying that procedure on a later instance. Development findings stay
non-promotable when reused; prospective qualification needs its own eligible
source and authorized lifecycle.

The [RC model guide](../../programmes/foundations/measurement-and-response/workflows/rc-ladder-response/guide.md#edit-a-development-model) keeps the original edited copy and prepared input.
In a successful diagnostic, inspect these exact report fields:

| Field | Interpretation |
|---|---|
| `config_id`, `cells`, `horizon_s` | Which numerical model, node count and time horizon were computed. |
| `receiver_unit`, `boundary_current_unit` | Voltage is in V. Boundary current is in A. |
| `final_cell_voltages_v` | Ordered final node voltages. They are not independent trials. |
| `maximum_backward_euler_defect_v` | Difference between the two numerical views, not physical-board validation. |
| `native_numerical_check_executed` | Whether this disclosed numerical diagnostic completed. |
| `campaign_candidate_compiled`, `campaign_issued` | Both remain false for the native diagnostic. |

The shipped model has four cells, a one-second horizon and frozen declared components.
The edited-resistance example computes another numerical model. It does not establish a physical result or a fresh cohort.
The separate study route has its own frozen voltage/charge-rate tolerances and independent falsifier tests.

For a deliberate refusal, set one copied `capacitances_farads` Decimal value to zero.
`config validate` refuses the invalid typed model before native contact.
If an invalid input reaches the native command with a usable retained destination, read its `failure.json` and diagnostics.
The invalid attempt has no successful numerical report. Repair the copied input, validate and prepare it again,
then use a fresh attempt path. Keep the failed attempt as evidence of the earlier invocation.

## Ask six questions

1. Which system, input identity and operation produced this result?
2. Did the operation complete, stop at a prerequisite, or leave completion unknown?
3. What quantity, units, clock and independent denominator does it report?
4. What scientific claim does the evidence support, and what is its ceiling?
5. Which exact input, output, receipt or adjudication contains the underlying record?
6. What next action is implemented, and what additional input or authority does it require?

A returned quantity is not automatically an admissible choice.
Operational completion, evaluability, support, scientific verdict and admission are separate observations.
A valid negative result is not an execution failure and must not enter operational retry.

## Incomplete exports and interruption

A usable output destination permits retention of early option/input errors and later failures.
An invalid or unwritable destination can prevent durable retention. Use the terminal diagnosis in that case.
Machine loss, forced termination or storage exhaustion can leave only a start record or partial products.
Missing finalization does not prove that no native contact occurred.

An export failure after computation means completed work may exist even though its report could not be written.
Keep genuine partial products and the diagnosis. Do not automatically repeat the computation.
Development retention supplies no resume transaction. Follow the family's documented fresh-path policy.
Issued recovery uses verified receipts to avoid repeating completed native effects.

Full Matrix programme export retains completed phase checkpoints before it assembles the final delivery.
Its [delivery procedure](../../programmes/foundations/emergent-structure/workflows/matrix-programme/guide.md#deliver-the-retained-scientific-products) permits exact checkpoint and file-copy reuse under current access.
Repeat the same selection and source. A changed input, completed copy or source refuses reuse.
The documented first-version checkpoint migration permits its exact writer, resume-validation and local-report exclusion repairs.
It retains every other package member, lock, runtime and operation binding.
Checkpoint completion and a partial copy do not establish a complete report delivery.

The [native subwork guide](../development/native-subwork.md) distinguishes full selected
operands, begin, contact, exact completion and received-prefix custody inside
an entered task. An interrupted output prefix remains separate from its
omitted scientific output. Caught errors can retain failed receipts; unknown
contact still forbids automatic replay after catalog loss or relocation.

For an initial recursive development experiment whose tasks are all settled,
exhausted or unreachable from exhausted prerequisites, `campaign experiment-recover
--custody-only` can finish operational custody without dispatching a task.
It authenticates retained producing provenance, plans and receipts as data using
the current reader, and refuses any eligible pending work. No producing checkout
or historical source bundle is required. It retains genuinely unreachable
descendants as not attempted; it creates no native completion or scientific score.
Use the original `--authoring-dir` without worker, retry or issued-authority
options. Its result defers scientific assessment. An explicit full read then
retains the complete original denominator, missing units and negative outcomes.
Ordinary execution still requires its original source binding.

### Read closed, incomplete E2 custody

An authenticated operational terminal does not establish complete scientific acquisition.
The full E2 reader can assess closed `BLOCKED` or `FAILED` custody under its original criterion.
It authenticates the original plan, latest task states, events, receipts and native contacts.
Every assigned root remains in the denominator.

Scored roots require their actual completed causal task chain and authenticated arrays.
Other roots retain distinct missing-root records with every unsuccessful phase.
These records distinguish unknown parent completion, contacted non-success, resource refusal and dependency blocks.
They do not invent a score, native completion or successful ordinary receipt.

Every missing root contributes zero usable units and zero successes.
The finite reduction still uses every originally assigned root and the unchanged primary allocation.
The report retains `INCOMPLETE_NATIVE_UTILITY_ASSESSMENT_WITH_CLOSED_WHOLE_ROSTER_REDUCTION`.
It grants no sampling warrant or qualification.
Compact and partial reads continue to defer this scientific assessment.

## Issued status and recovery

Use the same project, profile and authoring directory as the original issued operation.
For the assigned reactor route, the complete read-only status command is:

