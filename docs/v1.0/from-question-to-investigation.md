# From a scientific question to a recursive investigation

SPDX-License-Identifier: CC-BY-4.0

Start with the distinction you need to resolve. Select a scientific protocol only after its inputs, observations and assessments express that distinction. EL derives execution and custody from that definition. A workflow name, a registered method or a successful numerical calculation does not by itself specify the investigation.

## State the scientific question

Write the following scientific decisions before preparing inputs. They belong in the selected protocol's typed specification and source selection. This table is a design checklist, not another file format to maintain beside those inputs.

| Decision | What the researcher must specify | What must remain observable |
| --- | --- | --- |
| Question and alternative | The quantity, comparison, explanation or capability to investigate; the competing account or control where relevant | A result that could oppose the proposed account |
| System and population | The physical or numerical system, prepared population, source and independent unit | The full assigned census, including ineligible, failed and unevaluable units |
| Conditions of use | Domain, retained history, action and delivery, receiver, clock and horizon | Which conditions are assumed, supplied, measured or still missing |
| Information schedule | Inputs available at each forecast, selection and assessment cutoff | Outcomes cannot enter a predictor or selector before their declared reveal |
| Operation | An existing compatible method or domain capability, with its declared parameters and numerical settings | Exact implementation and scientific input identities |
| Evidence and assessment | The observation or calculation that can answer the question; the acceptance, refusal, uncertainty and falsification rules | Operational completion and scientific findings are separate fields |
| Dependencies | The prerequisite required by each consumer and the contribution proposed to supply it | A failed or unresolved supply cannot silently become an assumption |
| Consequential constraints | Precision, resolution, admissible approximation, spending or duration limit, and any access restriction | Resource placement cannot alter frozen numerical semantics |
| Reuse | The later consumer and its independently assessed applicability conditions | Parent identity, original scope, uncertainty and negative findings travel with the contribution |

For an exploratory inquiry, the immediate question can be local and revisable. Freeze the choices that govern each selected finite wave before its outcomes. Keep a subsequent change as a new declared investigation rather than editing the earlier commitment.

## Select the supported route

Use the [workflow catalogue](../reference/workflows.md) and [scientific route register](../reference/capabilities.md) to inspect available operations and their first stops. Then choose one of these routes.

| Your situation | Supported next action | Completion boundary |
| --- | --- | --- |
| An existing protocol expresses the question | Edit its strict scientific specification and select genuine original inputs; follow [investigation authoring](define-investigation.md) | The protocol derives a complete plan from the authored choices |
| A calculation is missing | Implement the typed operation through [Add a method](add-method.md) | The operation is independently callable and registered once; a protocol still supplies its scientific composition |
| A representation or native capability is missing | Follow [Add a domain](add-domain.md); keep native effects behind the applicable adapter port | The domain states meaning and applicability; the adapter supplies the actual external observation, action or conversion |
| A new scientific relationship is missing | Declare its protocol through [composition](compose-investigation.md#declare-a-new-scientific-investigation) | Inputs, method choices, causal edges and assessments are typed; plans and identities are derived |
| A consumer lacks a scientific prerequisite | Define that requirement and a supplier investigation through [recursive inquiry](../using/recursive-inquiry.md) | Supplier evidence, connection assessment and the consumer's result are distinct |
| Only a historical record or standalone analysis exists | Authenticate the original record for inspection, or implement the missing protocol explicitly | Historical availability is not evidence that a current recursive workflow exists |

A generic JSON file cannot select arbitrary Python or infer scientific compatibility. The public protocol declaration owns the scientific choices its specification accepts. Adding a new domain protocol is scientific integration work. It must not require another scheduler, custody implementation or recovery loop.

## Follow one authoritative definition

The [mass-balance investigation](define-investigation.md) is the smallest complete runnable example. It demonstrates authoring, preparation, execution, retained reading and recovery without optional native software. The [composition example](compose-investigation.md) demonstrates a separate derivative that preserves the original adverse or unevaluable finding.

Use this sequence for every supported protocol:

1. **Author:** retain the exact scientific specification and original source selection. Edit these inputs, not generated hashes, task identifiers or receipts.
2. **Prepare:** call the public investigation preparation service. Resolve its missing scientific inputs, environment or access requirements. Preparation has no permission to invent evidence.
3. **Inspect:** inspect the derived operation graph, independent-unit census, input origins, expected products, numerical requirements and authored-object trace.
4. **Execute:** use the shared investigation service with the selected operational profile. The profile selects available CPU or accelerated placement within the frozen scientific constraints.
5. **Assess:** read the original outputs through the same application service. Preserve all negative and unevaluable outcomes and distinguish a successful operation from a supported scientific claim.
6. **Recover:** use the retained plan, original attempts and existing recovery policy. An uncertain external effect requires its documented reconciliation; it is not permission to replay.
7. **Reuse:** assess the contribution against the next consumer's requirement. A supplied file or satisfied type is not sufficient evidence of scientific applicability.

The public Python sequence and exact commands are maintained in [Define or modify an investigation](define-investigation.md#use-the-application-api). The [public API reference](public-api.md) owns the supported imports. The selected family guide supplies its complete executable specification and required inputs.

## Trace the scientific meaning through the software

| Starting object | Derived or retained object | Owning layer | Researcher's inspection question |
| --- | --- | --- | --- |
| Question, units, scope and requirement | Strict scientific record | `science` and the relevant `domains` package | Does the record express the intended claim and independent unit? |
| Editable specification and operation selection | Scientific draft and derived plan | `design`, then `execution` | Are the actual choices and dependencies represented without a second editing surface? |
| Selected calculation | Typed method or domain invocation | `methods` or `domains` | Are assumptions, operands and numerical reference explicit? |
| Required external observation or action | Native contact and original output | `adapters`, through declared execution ports | What was actually contacted, delivered or observed? |
| Original artifact and producing attempt | Authenticated publication and recovery state | `storage` and shared execution services | Are all original products and uncertain effects retained? |
| Scientific assessment | Contribution and consumer applicability decision | Scientific assessment owner; application exposes the result | Did the evidence satisfy this specific requirement, and what remains unknown? |
| User-facing inspection | The same application operation in CLI or workbench | `api`, `cli`, `workbench` | Can I locate the authored object, failed owner and retained evidence? |

Use [results and failures](../using/results-and-failures.md) when execution or assessment stops. Correct the owning scientific definition or implementation. Do not make a failed result disappear by deleting a unit, changing an original commitment or substituting a new source.

## Preprint investigations

The [22-family census](../release/preprint-recursive-migration.md) now maps new
experiments inspired by all preprint families to one implemented recursive
protocol. Start with the [joint-description guide](joint-description-experiments.md)
to specify preparations, interventions, receivers, horizons and candidate
descriptions. Response-law construction and safe action selection supply lower
capabilities to the broader finite-menu economic hypothesis. Actual scientific
execution and review are separate from the focused software evidence.

Use the [experiment guide](joint-description-experiments.md) to run a recipe. The [programme record](../../programmes/shared-records/joint-description-results.md) identifies its source inputs, CPU findings and remaining qualification requirements.
