# Declared E4 development selection

SPDX-License-Identifier: CC-BY-4.0

The installed `matrix.e4.exposed-declared-revision` experiment protocol prepares
the development selection and joint revision/baseline freeze over original E4
records. Use the existing public experiment commands and
[programme service](../../../../src/empirical_lawhood/api/experiment_programme.py).
This is the standalone exposed selection route and its historical development evidence.
For the supported E1–E6 programme and its conditional calibration/confirmation phases, use the
[programme guide](../workflows/matrix-programme/guide.md) and [scientific specification](matrix-programme.md).
The older selections below do not define that programme's inputs.

Author a
[`ScheduledRevisionExperimentSpecification`](../../../../src/empirical_lawhood/adapters/methods/matrix_scheduled_history/selection_specification.py).
Select the original programme and criterion, paired target definition, inadequacy
trigger, whole-group folds, finite fit budget, candidate tunings and tie orders
explicitly. Each candidate embeds its scientific tuning. Changing its penalty
or supported feature selection requires no manual tuning digest, allocation
identity, graph, operation ID or binding changes. Preparation derives the strict
immutable method records and their identities.

The implemented family fits standardized ridge models from committed temperature,
friction and coupling, with supported signed pair terms and one aggregate center
term. It retains the original paired fifteen-endpoint target for each numerical
view. Separate quadratic coefficients are not identifiable from this design.
The researcher must select a scientifically appropriate family and trigger;
this route supplies no default or strongest-baseline warrant. A different
scientific feature extractor requires its own domain method and validation.

Bind four original records through an `ExperimentInputSelection` for this
protocol: `campaign`, `programme`, `reduction` and `data`. The paired data bank
retains each original coordinate, causal prefix and response score. The input
selection authenticates exact canonical bytes; domain preparation checks source,
role, group, physical clock, frame, cutoff and the original primary reduction.
FINE targets derive from their actual retained score cells. Missing observations
retain their whole groups as unevaluable.

The original development programme described here has 32 independent groups with nine
settings per group. Both numerical views and all30 paired targets remain nested
within those groups. Neither288 cases nor their individual target values become
new independent units. The shared selection method supports declared whole-unit
folds and complete candidate censuses. Revision and conventional baseline use
the same information, whole-group splits and fitting budget.

Select the existing Matrix environment, actual frozen source binding and guarded
output root separately, following the
[environment procedure](../../../../docs/development/maintainer-environment.md). Then use
`campaign experiment-explain` or `experiment-prepare` with `--input`, `--sources`,
`--source-snapshot`, `--environment-id` and `--output-root`, as documented for
[E3](../workflows/matrix-response-experiment/guide.md). No additional
`--protocol` override is declared for this checkpoint. `config validate` uses
consumer `matrix-e4-declared-selection`.

The same `campaign experiment-author`, `experiment-run`, `experiment-read` and
`experiment-recover` commands retain the frozen specification, both operations,
scientific products and completed-work recovery. A nontriggered or unevaluable
branch performs zero fits and retains its unentered joint freeze. A triggered
branch cross-validates every declared candidate on complete held-out groups and
freezes both selected final models before later calibration or confirmation.
The report distinguishes those scientific dispositions from operational success.

The installed `matrix.e4.exposed-factorial` protocol uses the same four original
records, input selection and public programme commands for the conditional
factorial calculation. Its editable
[`ScheduledFactorialSpecification`](../../../../src/empirical_lawhood/adapters/methods/matrix_scheduled_history/programme_factorial.py)
selects the explicit comparison nulls/directions, interaction scale, alpha and
descriptive practical thresholds. Consumer `matrix-e4-factorial` validates this
specification. Preparation derives the single assessment operation, complete
source bindings and retained experiment instance. It reports seven conditional
tests and all12 global Holm slots. Missing cross-phase comparisons remain
unevaluable. An absent source row retains its assigned coordinate and whole
group; even an empty data bank preserves all32 groups and288 assigned cases.
The required common-normal, independent whole-group sampling assumption is
reported as unauthenticated. A reference in the specification supplies no
admission verdict. Frozen-source13 public preparation, authoring, actual worker,
read and completed recovery pass for empty-bank, missing-coordinate and edited
complete selections. The missing coordinate retains all assigned cases and its
whole unevaluable group; the edited complete polynomial fixture retains seven
conditional rejections. Original custody stays unchanged through recovery.
These exposed controls retain their original source13 acceptance scope.
They do not establish scientific qualification or supply observations for the separate full programme.

These exposed development checkpoints are nonpromotable. They supply no genuine
source reservation, issue, outcome access, numerical qualification or biological
authority. Protected E4 factorial inference, matched acquisition, later independent
calibration/confirmation and protected programme entry retain their own
acceptance obligations. Use the [implementation map](../../../../docs/release/implementation-coverage.md)
and the selected release record for current software scope.
