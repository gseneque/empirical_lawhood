# Declaring the selected E4 source bank

SPDX-License-Identifier: CC-BY-4.0

This guide declares an E4 source bank before acquisition.
The recipe owner derives its complete three-phase scientific census.
Select a copied `SelectedE4BankRecipe` when the bank is not yet materialized.

The declarative E4 specification names exactly one existing bank or one recipe. The shared input role `bank-recipe-inputs` binds one immutable
`SelectedE4BankRecipeSourceInputs` record. The owner derives group, root, stream,
coordinate, panel, protocol, bank and programme identities; researchers do not
enumerate task IDs or construct a campaign package.

The recipe declares all four supported native preparation families, including
their complete coordinate schedules. It pins an actual original E3 preparation,
public frozen predictor, native prototype, response assay and prefix policy.
Temperature, friction and coupling levels, confidence, group count and whole
group wave size are explicit in each of the DEVELOPMENT, CALIBRATION and
CONFIRMATION designs. The native CAL construction criterion is also explicit.

The amended design declares balanced fixed four-family DEV groups and
`IID_UNIFORM_FOUR_FAMILIES_NO_REDRAW` for CAL/CONF. Each protected group receives
one uniform two-bit family draw from the separately committed family material.
Its nine coordinates remain nested cases of that group. Preserve realised
counts, including a zero count for a family; do not balance, replace or redraw.
The paired58 CAL construction criterion has no required realised family census.

The stream recipe requires separate full-width history and future seed material
and the exact declared group/purpose derivation rule. Every matched coordinate
uses its group's same four history streams. Independent future panels use the
separate future material. Existing allocation and panel owners check effective
numeric stream collisions and known exposures. This reproducible construction
creates no independence, exchangeability or freshness warrant.
The family, history and future seed materials must be distinct. The same group
draws replay during retained recipe loading; changed native stream material
does not silently change the family assignment.

The source-input bundle contains the actual original preparation, public E3
projection, all four original issued producer locators, response protocol and
exact preparation/assay/template publication descriptors. Original issue,
current execution/reveal grants, installed producer scope, complete receipt
closure and original scientific bytes are replayed before a new bank publication.
The assay and templates must match their actual original E3 task's configured
direct input publications. Original CAL scores remain in the parent reader;
the public projection carries their original identity without those scores.

The API owner captures the actual current producing provenance from the selected
checkout. It preserves every original source and dependency digest. A historical
commit label cannot become new producing provenance. Existing original
qualification records remain original metadata and are not copied into new
E4 source admissions.

After copying and validating the specification, request and typed inputs, use
the shared public derivation command with explicitly selected paths:

~~~sh
uv run --no-sync empirical-lawhood --project-root . --operator-profile "$PROFILE" --catalog-relative-path "$CATALOG" campaign experiment-derive-inputs --input "$SPECIFICATION" --sources "$ORIGINAL_SOURCES" --metadata-directory "$METADATA" --output-selection "$DERIVED_SOURCES" --source-snapshot "$SOURCE_SNAPSHOT" --environment-id "$ENVIRONMENT"
~~~

Choose all operational destinations under the guarded EL input/artifact plane.
The selected profile supplies concurrency; an explicit workers option must
agree with it. The source snapshot and environment are declared inputs.
Derivation publishes metadata and reports prerequisites. It performs no native
acquisition, qualification, issue, execution or reveal.

The publisher retains one complete three-phase allocation and its source
selections before first native entry. Stable result keys are
`allocation`, `selection`, `criterion`, `recipe`, `source-inputs`,
`provenance`, and `<PHASE>.responses`, `<PHASE>.bank`,
`<PHASE>.programme`. The final `index.json` pins the recipe, source bundle,
current provenance, all phase banks/programmes and their actual publications.
Record paths are the selected guarded absolute paths for those same keys.

Missing independent source qualification is an explicit CAL/CONF dependency.
An initial derived bank does not supply that qualification and does not create
an executable protected programme. Supply the independently produced evidence
over the exact retained bank on a later derivation. Keep the original bank and
publication descriptors; changing their location changes scientific subjects
and invalidates gates that name the earlier bank.

Interrupted metadata derivation can resume at the same destination. Every
generated publication is written and then actually replayed through the
immutable artifact owner. The embedded descriptor is that real replay result
on both the first and later calls. Original descriptors are never normalized.
Foreign paths, scopes or immutable bytes refuse. The complete index is last;
a partial prefix cannot masquerade as a complete bank publication.

The retained loader authenticates the complete index and all referenced
publications, cold decodes the original records and replays the whole recipe.
The pure bank validator checks scientific identity and complete denominators;
it grants no custody or authority. Subsequent protected entry still checks its
own current source, grants and original receipts.

Continue with the [protected phase programme](guide.md) for authoring and
request-driven run, read and recovery. An infinite original E3 radius stays
unbounded and original-only. Neither a bank recipe nor a completed publication
establishes E4 coverage or transport applicability.
