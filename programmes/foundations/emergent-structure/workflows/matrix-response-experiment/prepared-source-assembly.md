# Prepared finite-dt source inputs

The installed `matrix.source.prepared-finite-dt-input-assembly` route builds the
source prerequisite for selected E5 CONF and E6 transfer from copied inputs.
It uses the existing dataset authorization, source materialization and
prospective candidate owners. It starts no native task and performs no
scientific issue, attestation, reveal or qualification.

The copied [specification](prepared-source-assembly.example.json),
[request](prepared-source-assembly-request.example.json) and
[source selection](prepared-source-assembly-sources.example.json) are explicitly
unexecuted software examples. The selection binds only the compact request;
public preparation reports the two missing programme and development inputs.
The example's locators, metadata issuer and custody descriptors establish no
actual completed product or permission. Preserve their exposed status.

For a real selection, bind three canonical roles in `ExperimentFileInputSelection`:

| Role | Exact existing owner |
| --- | --- |
| `request` | current `MatrixPreparedSourceAssemblyRequest` version 2; actual whole C, original E3/preparation/assay publication handles, four E3 producer locators, source controls, metadata key policy and current census support |
| `original_e3` in the request | `MatrixProgrammeProducedInput`, retaining the original produced package publication's actual access and visibility; preparation, assay and C retain their blind `MatrixProgrammePublishedInput` contracts |
| `prepared-programme` | Selected protected/public or revision programme for E5 CONF or E6 transfer |
| `development-product` | Corresponding selected or revision `MatrixSelectedDevelopmentProduct`/`MatrixRevisionDevelopmentProduct` from actual complete E5 DEV |

Each binding retains its complete canonical bytes, exact identity, relative
input path and byte bound. The request pins the other two records and the
actual `MatrixFiniteDtTrainingLocator`; an authored-only locator or passing
summary cannot replace complete producing receipts and independent controls.
Original adverse and nonuse controls stay in the complete denominator.

Select the existing operator profile and four workers with one numerical thread
each. Use the public `campaign experiment-prepare` route first, then the existing
`campaign experiment-derive-inputs` command with the copied specification,
`--sources`, current implementation, environment and selected EL metadata
directory. Select `<metadata-directory>/sources.json` as the output. The result
reports its exact target `MatrixPreparedSourceQualificationSpecification` path
and source selector; use those files with ordinary public author/run/read/recover.
The [CLI reference](../../../../../docs/reference/cli.md) supplies the command options.

The explicit metadata key path is relative to the selected guarded EL root and
must be outside the publication directory. Missing keys refuse before output;
creation requires `allow_metadata_key_creation=true`. Requester and approver
must differ. The ordinary Ed25519 dataset issuer checks the actual clock,
metadata-only envelope and policy. An explicit validity start never supplies an
observation timestamp. Exact retries reuse original committed publications,
policy, authorization and materializer configuration; changed or expired inputs
retain their ordinary refusal.

CONF publishes an additive current exposure audit from authenticated actual
TRAIN/E3/E4/E5 DEV facts, including all three C E4 phase allocations and their response panels conservatively.
The downstream declarative request selects the emitted
`current-exposure/protected-sources.json`; its existing owner builds the
corresponding consumer programme. Original records remain unchanged. E6 keeps
its exact original pre-TRAIN audit, reserve and response panels.

The actual whole C joins the original native TRAIN request and all three E4
selections; no recipe index or synthetic CAL request is required. Its input
snapshots remain guarded through the derived candidate and requirements
publication. The selected source budget bounds complete C authentication.
One derivation reuses its complete TRAIN and E5 DEV source checks within that
guarded read lifetime. The early TRAIN candidate check remains; publication
snapshots and fresh file-support checks surround the CONF supplement and
certificate construction. Later certification and execution calls authenticate
their inputs afresh.

Genuine admission still requires the actual fresh E5 DEV controls and existing
source/issue authority. Finite-dt instrument support supplies no sampling, IID,
continuum or transport warrant. Use the [response guide](guide.md) and
[selected revision guide](../matrix-selected-revision/guide.md) for those phases.
