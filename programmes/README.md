## Read a programme

Start with the programme overview and its study table.
Each table links the **study design**, **findings**, **run guide** and **evidence availability**.
Software availability and scientific support are stated separately.
A historical result can exist without a public reproduction route.

A **study design (protocol)** specifies the question, independent units,
observations, analysis and outcome rules. Its status identifies whether it is
proposed, frozen for a named study or superseded.
A **run guide** gives commands and editable inputs for a supported operation.
A **finding** records what happened under the selected design, including
negative, missing and unevaluable outcomes.

Each programme owns three main locations:

- `workflows/`: task guides and their editable inputs.
- `records/`: scientific designs, results, source assessments and retained decisions.
- `reference/`, where needed: programme-specific technical formats.

Workflow directories are task bundles, not independent experiments or run archives.
Several workflows can contribute to one study.
The shared [recursive inquiry procedure](../docs/using/recursive-inquiry.md)
uses RC, battery and materials inputs from their respective programmes.
[Shared records](shared-records/README.md) preserve dated reports involving several programmes.

## Use the engine

Follow the [researcher procedure](../docs/using/designing-and-running-an-experiment.md#researcher-procedure)
after choosing a supported guide.
Select its environment, operator profile and explicit input/output destinations.
Use the [workflow catalogue](../docs/reference/workflows.md) for all installed
workflow IDs and the [capability register](../docs/reference/capabilities.md)
for retained routes and their missing prerequisites.
The [paper source register](../paper/SOURCES.md) maps all twenty-two preprint
study families to current software and original evidence availability.
